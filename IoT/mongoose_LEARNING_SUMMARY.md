## 1. What Mongoose Is

Mongoose is a **single‑drop‑in C networking library** for both microcontrollers
and desktop/server platforms. It bundles:

- A non‑blocking **event manager** (`struct mg_mgr`)
- A complete **TCP/IP stack** (ARP, IP, ICMP, TCP, UDP, DHCP, NDP — implemented in `src/net_builtin.c`, ~2,500 lines)
- Application protocols: **HTTP/HTTPS**, **WebSocket**, **MQTT**, **MQTT‑SN**,
  **SNTP**, **mDNS**, **Modbus‑TCP**, **RPC/JSON‑RPC**
- **TLS 1.3** with three backends: built‑in (ECC/X25519/AES‑128‑GCM/ChaCha20),
  mbedTLS, OpenSSL, WolfSSL (see `src/tls_*.c`, ~10,000 lines)
- **Firmware OTA** for STM32 (F1/F4/F7/H5/H7/N6), NXP iMX RT, RP2040/RP2350,
  ESP32, CH32V307 (see `src/ota_*.c`, ~1,500 lines)
- A **device‑dashboard** framework with a JavaScript frontend (`src/dash.c`,
  ~700 lines plus `tutorials/device-dashboard`)
- Filesystem abstraction supporting POSIX, packed (C‑arrays), FatFS, LittleFS
  (`src/fs*.c`)
- Primitives: SHA1/SHA256/SHA384, MD5, HMAC, base64/url‑base64, JSON
  parser/serializer, RPC, JWT, SPSC queue, SPSC event profiler.

The whole thing ships as **two files**: `mongoose.c` + `mongoose.h`.
No Makefile, no external libs (except optional TLS backend). Build it
literally with `cc main.c mongoose.c`.

> "Two files. Drop `mongoose.c` and `mongoose.h` into any C/C++ project and
> get a full network stack — HTTP, WebSocket, MQTT, TLS, firmware OTA
> updates, device dashboard — on any microcontroller or desktop OS." — README

## 3. Architecture in One Picture

```
                     +-------------------------------------+
                     |  Application event handler          |
                     |  void fn(c, ev, ev_data);           |
                     +-----------------+-------------------+
                                       |
                                       v   (mg_call)
                     +-------------------------------------+
                     |  struct mg_connection               |
                     |   - linked list in struct mg_mgr    |
                     |   - user fn   + protocol pfn       |
                     |   - recv iobuf / send iobuf / rtls  |
                     |   - data[MG_DATA_SIZE] scratch      |
                     +-----------------+-------------------+
                                       |
            +--------------------------+----------------------------+
            |                          |                            |
            v                          v                            v
   Protocol modules             TLS layer                    mg_io layer
   mg_http_cb, mqtt, ws,       built-in / mbed /              BSD sockets
   modbus, mdns...             openssl / wolf                 or builtin stack
            |                          |                            |
            +------------+             +                            |
                         |             |                            |
                         v             v                            v
                    mg_send     conn->send iobuf       (sockets)        (net_builtin)
                                  mg_xprintf writes         |              TCP state machine
                                  raw bytes here            v              in struct connstate
                                                       mg_iotest()      (src/net_builtin.c)
                                                       epoll/poll/sel
```

Everything is a `struct mg_connection`. The connection holds **recv** and
**send** byte buffers (`struct mg_iobuf`) that act as your interface to the
network: write into `send` with `mg_send/mg_printf`, read from `recv`
inside `MG_EV_READ` or `MG_EV_HTTP_MSG` etc.

## 4. Core Data Structures

### 4.1 `struct mg_str` — non‑owning byte slice (line 1577)

```c
struct mg_str { char *buf; size_t len; };
```

- Not necessarily NUL-terminated.
- Used pervasively as a zero-copy view over network packets, HTTP headers,
  JSON tokens, etc.
- Helpers: `mg_str()`, `mg_str_n()`, `mg_strdup()` (allocating copy),
  `mg_strcmp/casecmp`, `mg_match` (glob), `mg_span` (split by separator).

Because functions take `const char *len` slices, Mongoose avoids copies
endlessly — headers, bodies, query strings are all just `mg_str` slices
into `c->recv.buf`.

### 4.2 `enum mg_event` — single event channel (line 2371)

```c
enum mg_event {
  MG_EV_ERROR, MG_EV_OPEN, MG_EV_POLL, MG_EV_RESOLVE, MG_EV_CONNECT,
  MG_EV_ACCEPT, MG_EV_TLS_HS, MG_EV_READ, MG_EV_WRITE, MG_EV_CLOSE,
  MG_EV_HTTP_HDRS, MG_EV_HTTP_MSG, MG_EV_WS_OPEN, MG_EV_WS_MSG,
  MG_EV_WS_CTL, MG_EV_MQTT_CMD, MG_EV_MQTT_MSG, MG_EV_MQTT_OPEN,
  MG_EV_SNTP_TIME, MG_EV_WAKEUP, MG_EV_MDNS_REQ, MG_EV_MDNS_RESP,
  MG_EV_MODBUS_REQ,
  MG_EV_USER  // user-defined start
};
```

Each protocol enters the same one-callback chokepoint. Every protocol table
in `mongoose.c` writes a comment that maps each event to `ev_data` type —
this is the keystone of the API.

### 4.3 `struct mg_addr` — IPv4/IPv6 in one union (line 2415)

```c
struct mg_addr {
  union { uint8_t ip[16]; uint32_t ip4; uint64_t ip6[2]; } addr;
  uint16_t port;
  uint8_t scope_id;
  bool is_ip6;
};
```

Values in **network byte order**. All port/byte helpers come in network
↔ host variants (`mg_htons`, `mg_htonl`, `mg_load_be32`).

### 4.4 `struct mg_mgr` — the event manager (line 2432)

```c
struct mg_mgr {
  struct mg_connection *conns;   // doubly-linked list of all conns
  struct mg_dns dns4, dns6;      // 8.8.8.8 and 2001:4860:4860::8888 by default
  struct mg_connection *mdns;    // mDNS listener, NULL if disabled
  int dnstimeout;                // 3000 ms default
  bool use_dns6;
  unsigned long nextid;          // auto-inc connection ID
  void *userdata;
  void *tls_ctx;
  struct mg_timer *timers;
  int epoll_fd;                  // Linux
  struct mg_tcpip_if *ifp;       // built-in TCP/IP interface pointer
  ...
};
```

Normally you call `mg_mgr_init` once then `mg_mgr_poll(&mgr, 1000);` in a
loop, or from an RTOS task.

### 4.5 `struct mg_connection` — everything is a connection (line 2458)

```c
struct mg_connection {
  struct mg_connection *next;
  struct mg_mgr *mgr;
  struct mg_addr loc, rem;          // local & remote
  void *fd;                          // OS socket OR lwIP PCB OR mg_tcpip_conn pointer
  unsigned long id;
  struct mg_iobuf recv, send, prof, rtls;
  mg_event_handler_t fn;             // user callback
  void *fn_data;
  mg_event_handler_t pfn;            // protocol-level handler (HTTP/WS/MQTT/...)
  void *pfn_data;
  char data[MG_DATA_SIZE];           // protocol-state scratch
  void *tls;
  unsigned dscp:6;
  unsigned is_listening:1, is_client:1, is_accepted:1,
           is_resolving:1, is_arplooking:1, is_connecting:1,
           is_tls:1, is_tls_hs:1, is_udp:1, is_websocket:1,
           is_mqtt5:1, is_hexdumping:1, is_draining:1,
           is_closing:1, is_full:1, is_tls_throttled:1,
           is_readable:1, is_writable:1;
};
```

The packed bit field at the bottom holds state flags for the I/O layer;
`data[MG_DATA_SIZE]` is a per-connection scratch buffer that protocols
reuse for state machines. (HTTP parser state is small enough to fit here.)

### 4.6 `struct mg_http_message` — parsed HTTP (line 2655)

```c
struct mg_http_message {
  struct mg_str method, uri, query, proto;        // request line
  struct mg_http_header headers[MG_MAX_HTTP_HEADERS];
  struct mg_str body, head, message;
};
```

Both `mg_http_listen` (server) and `mg_http_connect` (client) deliver this
to your handler via `MG_EV_HTTP_MSG`. Helpers: `mg_http_get_header`,
`mg_http_var`, `mg_http_status`, `mg_match(hm->uri, ...)`, `mg_http_reply`.

## 5. The Event Loop (`mg_mgr_poll`)

`mg_mgr_poll` is the single point of concurrency. It comes in **two
implementations** (one or the other is compiled depending on the TCP/IP
choice).

### 5.1 BSD-socket implementation (line 15341, `src/sock.c`)

```c
void mg_mgr_poll(struct mg_mgr *mgr, int ms) {
  mg_iotest(mgr, ms);                         // epoll_wait/poll/select
  now = mg_millis();
  mg_timer_poll(&mgr->timers, now);
  mg_ota_poll(mgr);  mg_mdash_poll(mgr);

  for (c = mgr->conns; c != NULL; c = tmp) {
    tmp = c->next;
    mg_call(c, MG_EV_POLL, &now);             // heartbeat

    if (c->is_resolving || c->is_closing) {
      // nothing
    } else if (c->is_listening && !c->is_udp) {
      if (c->is_readable) accept_conn(mgr, c);
    } else if (c->is_connecting) {
      if (c->is_readable || c->is_writable) connect_conn(c);
    } else {
      if (c->is_readable) read_conn(c);
      if (c->is_writable) write_conn(c);
      if (c->is_tls && !c->is_tls_hs && c->send.len == 0)
        flush = mg_tls_flush(c);
    }

    if (flush == MG_IO_ERR) mg_error(c, "tx err");
    if (c->is_draining && c->send.len == 0 && flush == 0)
      c->is_closing = 1;
    if (c->is_closing) close_conn(c);
  }
}
```

Key insights:

- A single `for` loop walks the connection list. Connection creation/
  destruction happens **inside the loop** (via `close_conn` removing from
  the list), so it carefully caches `tmp = c->next` first.
- One function, `mg_call`, invokes the user handler — every protocol
  layers into the same callback.
- `read_conn` puts bytes into `c->recv` and fires `MG_EV_READ`. Protocol
  modules consume from `c->recv` in their `pfn` callback.
- `write_conn` drains `c->send` to the socket. There is no per-write
  syscall — the user just appends bytes via `mg_printf`/`mg_send` and the
  next poll flushes them.

### 5.2 Built‑in TCP/IP implementation (line 10823, `src/net_builtin.c`)

The same shape, but instead of `mg_iotest` it calls `mg_tcpip_poll()`,
which is a full state machine for IP/TCP/UDP/ARP/ICMP/NDP/DHCP. After
that, the function iterates over connections and stages the send buffer
into the TCP tx queue (`struct connstate::txq`), applies TLS if enabled,
and closes anything that has finished the 3‑way close.

### 5.3 Internal dispatch: `mg_call` (`src/event.c`)

```c
void mg_call(struct mg_connection *c, int ev, void *ev_data) {
  // protocol handler first, user handler second (see #2559)
  if (c->pfn != NULL) c->pfn(c, ev, ev_data);
  if (c->fn  != NULL) c->fn (c, ev, ev_data);
}
```

This convention means **protocols get first dibs** on incoming events
(`MG_EV_READ`) to parse a frame, mark it consumed by advancing
`c->recv` pointers, and **then** the application sees a clean
`MG_EV_HTTP_MSG` etc.

## 7. URLs Are Universal

Every API call that opens a connection takes a URL string:

```
tcp://host:port           raw TCP
udp://host:port           raw UDP
http://host[:port]/path   HTTP   (port 80 default)
https://...               HTTPS
ws://host/path            WebSocket (port 80)
wss://...                 secure WS
mqtt://host[:port]        MQTT 3.1.1 (port 1883)
mqtts://...               MQTT over TLS (port 8883)
ssl://...  tls://...      generic TLS
```

The parser lives in `src/url.c` (`mg_url_port`, `mg_url_is_ssl`,
`mg_url_host`, `mg_url_user`, `mg_url_pass`, `mg_url_uri`). This makes
`mg_connect`, `mg_http_listen`, `mg_mqtt_connect`, `mg_ws_connect`
interchangeable.

## 8. The `mg_iobuf` — Universal Buffer (line 2256)

```c
struct mg_iobuf {
  unsigned char *buf;
  size_t size;     // capacity, multiple of align
  size_t len;      // populated
  size_t align;    // for granular realloc
};
```

Every connection has `recv`, `send`, `prof`, `rtls`. Every `mg_iobuf_*`
operation (`init`, `resize`, `add`, `del`, `free`) is implemented in
`src/iobuf.c` and uses **`mg_calloc + mg_bzero + mg_free`** rather than
`realloc`. This guarantees that on shrink the dropped bytes are zeroed
before `free()` (sensitive data is not leaked) and prevents stale
allocation attacks on shrink.

`resize` rounds up to `align` (defaults to `MG_IO_SIZE = 1460` / `16384`
depending on platform). Avoids fragmentation and matches typical TCP MSS.

## 9. Format Engine (`mg_xprintf`, `mg_snprintf`)

In `src/fmt.c` + `src/printf.c`, Mongoose implements its **own**
printf‑compatible engine instead of using libc. It supports:

- Standard: `%c %s %d %u %x %ld %lu %lld %llu %p %f %g %%`
- Width/precision: `%1.2d`, `%.*d`
- Non‑standard: `%M` → calls a custom `mg_pm_t` printer
  (e.g., `mg_print_ip`, `mg_print_mac`, `mg_print_esc`,
  `mg_print_hex`, `mg_print_base64`, `mg_print_ip_port`).
- `%m` is exactly like `%M` but **double‑quotes** the output → for JSON.
- `MG_ESC("foo")` expands to `mg_print_esc, 0, "foo"` for `mg_snprintf("%m", ...)`.

Output targets are pluggable through `mg_pfn_t`:

- `mg_pfn_iobuf` — appends to `struct mg_iobuf` (used internally).
- `mg_pfn_iobuf_noresize` — fixed-size buffer.
- `mg_pfn_stdout` — prints to stdout.

The `MG_INFO(...)` macro is `MG_LOG(MG_LL_INFO, ("format", args...))`
which double‑parenthesizes — slightly odd but efficient.

## 10. HTTP Module Deep Dive (`src/http.c`)

### 10.1 Server Setup

```c
mg_http_listen(&mgr, "http://0.0.0.0:8000", ev_handler, NULL);
```

The implementation (`src/net.c` 8286) is:

```c
struct mg_connection *mg_listen(struct mg_mgr *mgr, const char *url,
                                mg_event_handler_t fn, void *fn_data) {
  struct mg_connection *c = NULL;
  if ((c = mg_alloc_conn(mgr)) == NULL) ...
  else if (!mg_open_listener(c, url)) ...
  else {
    c->is_listening = 1;
    c->is_udp = strncmp(url, "udp:", 4) == 0;
    LIST_ADD_HEAD(...);
    c->fn = fn; c->fn_data = fn_data;
    c->is_tls = mg_url_is_ssl(url);
    mg_call(c, MG_EV_OPEN, NULL);
  }
}
```

`mg_http_listen` (line 4801) is just:

```c
struct mg_connection *c = mg_listen(mgr, url, fn, fn_data);
if (c != NULL) c->pfn = http_cb;
```

So the **HTTP state machine** is attached via `c->pfn = http_cb`.

### 10.2 The State Machine (`src/http.c` `http_cb`)

When bytes arrive on a TCP connection:

1. `MG_EV_READ` fires → `pfn == http_cb` runs, appends to `c->recv`,
   scans for complete requests (using `mg_http_parse`).
2. For each complete request, fires `MG_EV_HTTP_HDRS` (headers only)
   then `MG_EV_HTTP_MSG` (full message).
3. App handler runs — usually calls `mg_http_reply(c, 200, hdrs, body)`.

`mg_http_reply` (line 4008) is a small trick:

```c
void mg_http_reply(struct mg_connection *c, int code, const char *headers,
                   const char *fmt, ...) {
  va_list ap; size_t len;
  mg_printf(c, "HTTP/1.1 %d %s\r\n%sContent-Length:            \r\n\r\n",
            code, mg_http_status_code_str(code),
            headers == NULL ? "" : headers);
  len = c->send.len;
  va_start(ap, fmt);
  mg_vxprintf(mg_pfn_iobuf, &c->send, fmt, &ap);   // body
  va_end(ap);
  if (c->send.len > 16) {
    // Overwrite the 10-char placeholder "            " with the real length
    size_t n = mg_snprintf((char *) &c->send.buf[len - 15], 11, "%-10lu",
                           (unsigned long) (c->send.len - len));
    c->send.buf[len - 15 + n] = ' ';
  }
}
```

It writes a literal `"Content-Length:            \r\n"` (12 spaces) then
back‑fills the length once the body is known — saves a copy of the body
into a temp buffer.

### 10.3 Static File Serving (`mg_http_serve_file`, line 4139)

- Tries `.gz` first if `Accept-Encoding: *gzip*`.
- Falls back to 404 page if configured.
- Honors `Range:` (returns 206).
- Generates `ETag: "<mtime>.<size>"`.
- Honors `If-None-Match` for 304.
- MIME type from extension via `guess_content_type` — built‑in table of
  ~30 extensions, plus user overrides via `mg_http_serve_opts.mime_types`.

### 10.4 `mg_http_serve_dir` (line 4363)

- Path sanitation via `mg_path_is_sane` to block `..` traversal.
- If directory: try `index.html` / `index.htm`, or auto‑generated listing.

## 11. URL Pattern Matching (`mg_match`, line 15574)

Tiny but powerful:

```c
bool mg_match(struct mg_str s, struct mg_str p, struct mg_str *caps);
```

Wildcards:
- `?` → exactly one character.
- `*` → any number of characters, **excluding `/`**.
- `#` → any number of characters, including `/`.
- `caps` (optional, can be NULL) is filled with **zero‑copy slices** of
  `s` for each captured wildcard.

Examples:

```c
mg_match(hm->uri, mg_str("/api/#"), NULL);              // anything under /api/
mg_match(hm->uri, mg_str("/rest/*"), caps);            // /rest/<single segment>
mg_match(hm->uri, mg_str("/static/**"), NULL);          // NB: not implemented!
```

The implementation is small (~50 lines) and uses backtracking on `*`/`#`.

## 12. The Built‑in TCP/IP Stack (`src/net_builtin.c`)

This is the heart of mongoose on bare metal. ~2,500 lines that implement:

### 12.1 Packet Layout

```c
struct pkt {                  // parsed incoming packet
  struct mg_str raw, pay;
  uint8_t *l2;                // Ethernet/PPP frame
  struct arp  *arp;
  struct ip   *ip;
  struct ip6  *ip6;
  struct icmp *icmp, *icmp6;
  struct tcp  *tcp;
  struct udp  *udp;
  struct dhcp *dhcp, *dhcp6;
};
```

All headers are `#pragma pack(1)` — pointers overlap raw bytes (zero copy).

### 12.2 Per‑Connection TCP State

```c
struct connstate {           // sits in (char *)(c+1) i.e. extraconnsize
  uint32_t seq, ack, maxseq, txq_seq, txq_una, acked;
  uint64_t timer, txq_timer;
  size_t   unacked;
  uint16_t win, dmss;
  uint8_t  mac[6], ttype, tmiss, txq_retries;
  bool fin_rcvd, twclosure, retransmit, is_full;
  struct mg_iobuf txq;       // RFC-9293 §3.8 retransmit queue
};
```

This **lives right after** the connection struct (`(char *)(c+1)`).
That's why `mgr->extraconnsize` exists — the caller can grow the conn
struct at allocation time so each built‑in TCP connection has its state
inline.

### 12.3 TCP Timers

```c
#define MG_TCPIP_KEEPALIVE_MS 45000
#define MG_TCPIP_ACK_MS        150     // delayed-ack
#define MG_TCPIP_ARP_MS        100
#define MG_TCPIP_SYN_MS       15000
#define MG_TCPIP_FIN_MS        1000
#define MG_TCPIP_RTX_MS        1000    // RFC-6298 §2.1
#define MG_TCPIP_RTX_MAX_MS   60000    // RFC-6298 §2.5
#define MG_TCPIP_WIN          6000
#define MG_TCPIP_MIN_MSS        64

#define MG_TCPIP_TXQ_ALIGN    1024
```

Retransmission uses RFC-6298; **no R2 constant** (deliberate — KEEPALIVE
eventually closes non-responsive peers).

### 12.4 TCP State Machine

`syn_sent → established → fin_wait_1 → fin_wait_2 → time_wait → closed`.
Standard 3‑way handshake, 4‑way close. `mg_tcpip_poll` advances every
connection's `ttype` timer:

```c
static void settmout(struct mg_connection *c, uint8_t type) {
  ...
  s->timer = ifp->now + n;
  s->ttype = type;
}
```

### 12.5 Checksumming

`csumup` / `csumfin` / `ipcsum` / `pcsum` (IPv4 pseudo‑header) /
`p6csum` (IPv6) — all inline, no memcpy tricks.

### 12.6 DHCP / NDP / SLAAC

In `mg_tcpip_poll`: state machine `MG_TCPIP_STATE_DOWN → UP → IP → READY`.
On READY, gratuitous ARP is sent and `MG_TCPIP_EV_STATE_CHANGE` fires.

### 12.7 Multicast / IGMP / MLD

`struct mac_hash { uint8_t used, group[8], mac[8]; };` — small 8‑entry
hardware multicast filter table.

### 12.8 Drivers

`s/src/drivers/` contains pluggable drivers:
STM32F (F1/F2/F4/F7), STM32H5, STM32H7, STM32N6, NXP IMXRT, NXP MCXN,
NXP RW612, RP2040/RP2350 (W55RP20), CYW43 (Pico W, Portenta H7), and
Wiznet W5500. The selection is compile‑time via `MG_ENABLE_DRIVER_*`.

The driver API (`struct mg_tcpip_driver`) is small: `tx`, `rx_poll`,
`set_rx_done_cb`. Each driver calls `mg_tcpip_rx()` from its RX ISR.

Targets supported:

| Define | Target |
|---|---|
| `MG_OTA_STM32F` | STM32F1/F2/F4/F7 |
| `MG_OTA_STM32H5` | STM32H5 (IWDG rollback, BKP0R state) |
| `MG_OTA_STM32H7` | STM32H7 |
| `MG_OTA_STM32N6` | STM32N6 |
| `MG_OTA_IMXRT*` | NXP iMX RT (WDOG1 + SNVS LPGPR0 state) |
| `MG_OTA_MCXN` | NXP MCX N |
| `MG_OTA_RW612` | NXP RW612 |
| `MG_OTA_PICOSDK` | RP2040 / RP2350 (watchdog scratch) |
| `MG_OTA_ESP32` | ESP32 (esp_ota_*) |
| `MG_OTA_CH32V307` | WCH CH32V307 |
| `MG_OTA_NONE` | stub |

The **A/B rollback** mechanism is elegant:

```c
// In src/ota.c, mg_ota_poll() at line 11166:
if (MG_OTA_STATE_GET() == MG_OTA_FAILED &&
    mg_timer_expired(&feed_timer, 500, mg_millis())) {
  if (feed_timer < (uint64_t) MG_OTA_ROLLBACK_TIMEOUT_SECONDS * 1000) {
    MG_OTA_ROLLBACK_TIMER_FEED();   // keep feeding watchdog
  } else if (s_autocommit_ok) {
    MG_INFO(("Auto-committing firmware"));
    MG_OTA_STATE_SET(MG_OTA_CONFIRMED);
  } else {
    // Stop feeding -> watchdog fires -> reset -> rollback
  }
}
```

If the new firmware doesn't confirm itself in time, the watchdog fires and
the bootloader reverts. `s_autocommit_ok` is set when an OTA manager
endpoint replies with "same version" as a positive acknowledgement.

## 19. Notable Design Choices

### 19.1 Two‑file distribution

- Zero external dependencies (other than C stdlib and optional TLS lib).
- Amalgamation pattern means `mongoose.c` is large but buildable with
  one file. The `#line` directives keep build errors usable.

### 19.2 Single‑threaded cooperative event loop

- No locks anywhere in the core. Callbacks run in `mg_mgr_poll`'s context.
- SPSC queue (`mg_queue_*`) is the only mechanism for ISR → main thread
  message passing.

### 19.3 Connection‑centric object model

- One struct (`mg_connection`) is reused for **TCP/UDP/Listener/Client**
  and as the carrier for **HTTP / WebSocket / MQTT / plain socket**
  protocols. You never instantiate a "WebSocket object" — a TCP
  connection becomes a WebSocket connection after handshake.

### 19.4 `mg_str` zero‑copy slices

- HTTP headers, JSON tokens, URL components are all slices into the
  recv buffer. Copying happens only at API boundaries (e.g. user calls
  `mg_http_reply` with a format string).

### 19.5 Heap discipline

- `mg_calloc + mg_bzero + mg_free` (not realloc) ensures stale data is
  zeroed before reuse/free.
- Resize granularity = `MG_IO_SIZE` matches the typical TCP MSS, so
  resizes fall on natural boundaries.

### 19.6 Layer‑2 (Ethernet/PPP) abstraction

- `mg_l2_header`, `mg_l2_trailer`, `mg_l2_rx` decouple IP from the
  underlying framing — the same TCP/IP code serves raw Ethernet,
  PPPoE, and PPP (cellular modems).

### 19.7 Profiling built in

- `MG_PROF_ADD(c, "MY_EVENT")` records an event in `c->prof` iobuf.
- `MG_PROF_DUMP(c)` walks the buffer and logs a sorted timeline. Bypasses
  external tools for fast embedded perf debugging.

### 19.8 Compile‑time everything

- No runtime plugin system. Every feature is a `#define`. This keeps the
  library small (one .c/.h) and statically analyzable.

### 19.9 Bundled TLS, mDNS, OTA, Dashboard

- The library has everything needed to ship an IoT product. The README
  is explicit: "do not use a separate HTTP/MQTT/WS library alongside
  Mongoose" — they all already exist here.

### 19.10 Compatible with GCC, Clang, MSVC, IAR, ARMCC

- `arch_*.h` files handle each compiler's quirks. The header uses
  `__attribute__((...))` only inside macros so MSVC and IAR skip them.

## 20. Gotchas & Common Pitfalls (from headers' comments)

1. **Strings**: always pass string literals via `mg_str("literal")`, not
   raw `char *`. The latter would compute `strlen` on every call —
   harmless for short strings but wasteful when called in a hot path.

2. **Blocking calls in handlers**: don't `sleep()`/`HAL_Delay()` inside
   `MG_EV_*` handlers. They will stall the entire event loop. Use
   `mg_timer_add`.

3. **Single task only**: never call `mg_*` from a different task/thread
   than the one running `mg_mgr_poll`. The exception is `mg_wakeup` (uses
   socketpair) and `mg_queue_*` (SPSC, designed for ISR).

4. **Don't stack the built‑in stack with lwIP/FreeRTOS**: exactly one
   `MG_ENABLE_TCPIP` / `MG_ENABLE_LWIP` / `MG_ENABLE_FREERTOS_TCP`.

5. **Packed bit fields in `mg_connection`**: don't reorder them — code
   (drivers, TLS code) `memcpy`s them around.

6. **`MG_DATA_SIZE`** defaults to a tiny value. If you have a non-trivial
   protocol on top of a connection, raise it (e.g. `mg_http_message` has
   up to `MG_MAX_HTTP_HEADERS * sizeof(mg_http_header)` worth of state).

7. **`is_closing` does not free immediately**: it just sets a flag. The
   connection is freed in `mg_close_conn` at the **next** `mg_mgr_poll`.
   Same for `is_draining`.

8. **`mg_send` is asynchronous**: bytes are appended to `c->send` and
   shipped by the next poll iteration. It does not block on socket ready.

9. **TLS renegotiation is not supported** in the built‑in stack.

10. **`dashboard.html` is a black box** — do not add `fetch` calls or
    event listeners; use only `data-bind` / `data-save` / `${...}`.

## 24. What I Found Useful / Worth Highlighting

1. **`mongoose.h` first, always**: it's effectively the
   auto-generated API reference with examples, tutorials referenced,
   and pitfalls called out (see `AGENTS.md` rule).

2. **Two `#define` short-string macros** carry a lot:
   `mg_str(s)` and `MG_ESC(s)`. They eliminate whole categories of bugs
   (slicing strings on the right place, JSON escaping).

3. **Connection state machine**: every protocol that wraps a TCP
   connection is itself a state machine encoded partially in
   `mg_connection` (bit fields) and partially in `mg_connection::data[]`.
   Look at `src/http.c` `http_cb` (~400 lines) for the cleanest example.

4. **TCP retransmit queue** (`struct connstate::txq`) is a buffered,
   length‑prefixed packet log (RFC‑9293 §3.8). Bytes are only freed
   when their cumulative position is acked. This is the core of the
   built‑in stack's reliability and worth studying.

5. **OTA rollback via watchdog**: the watchdog‑as‑rollback idea is
   clever and worth reusing elsewhere. IWDG is enabled with a 10s
   window; `mg_ota_poll` feeds it every 500ms; if the new firmware
   doesn't confirm in time, the watchdog resets and the bootloader
   rolls back. State is stored in backup registers (BKP0R / SNVS).

6. **`mg_call` ordering** matters: protocol handler first, user
   handler second (see comment at line 2364-65 referencing issue #2559).
   Otherwise users consuming `MG_EV_READ` first would steal bytes from
   the protocol parser.

7. **The dual implementation of `mg_mgr_poll`** is a clean pattern: one
   BSD-socket path, one built‑in stack path, selected at compile time
   by feature macros. The rest of the codebase is unaware.

## 27. Mental Model Cheat Sheet

```
#include "mongoose.h"

static void handler(struct mg_connection *c, int ev, void *ev_data) {
  switch (ev) {
    case MG_EV_OPEN:           break;          // fd allocated
    case MG_EV_ACCEPT:         break;          // incoming conn on listener
    case MG_EV_CONNECT:        break;          // outbound TCP up
    case MG_EV_READ: {                           // raw bytes in c->recv
      long n = *(long*)ev_data;
      // append to your state, mg_iobuf_del() consumed bytes
      break;
    }
    case MG_EV_HTTP_MSG: {                     // parsed req/resp
      struct mg_http_message *hm = ev_data;
      mg_http_reply(c, 200, "...", "...");
      break;
    }
    case MG_EV_WS_MSG:        break;           // WebSocket frame
    case MG_EV_MQTT_MSG:      break;           // MQTT publish
    case MG_EV_CLOSE:         break;           // conn going away
  }
}

int main(void) {
  struct mg_mgr mgr;
  mg_mgr_init(&mgr);
  mg_http_listen(&mgr, "http://0.0.0.0:8000", handler, NULL);
  for (;;) mg_mgr_poll(&mgr, 100);
}
```

That's the **whole story**. Add TLS by setting `c->is_tls=1` before
`mg_listen` or by calling `mg_tls_init` in `MG_EV_ACCEPT`. Add MQTT
by calling `mg_mqtt_connect` (overrides `pfn` to `mqtt_cb`). Switch
protocols without leaving the single‑thread model.
